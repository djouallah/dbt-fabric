# What the RUNNER needs for the iceberg leg -- NOT what dbt runs on.

# WHY THIS FILE EXISTS: dbt-oss and duckrun cannot share one Python environment. duckrun
# pins dbt-core<2 and dbt-duckdb<2, which lay a dbt-core 1.x `dbt` console script over dbt
# v2's and leave `dbt --version` reporting 1.x in a job that is supposed to be v2. So the
# leg splits by CONSUMER: the notebook and the gating job get requirements/iceberg.txt
# (dbt-oss alone), and the runner gets this.
#
# The runner never runs dbt for this engine. It:
#   * provisions the Fabric items          (.github/scripts/provision.py, needs duckrun auth)
#   * launches the notebook                (.github/scripts/remote_dbt.py -> run_python)
#   * compacts afterwards                  (.github/scripts/compact_iceberg.py, needs duckdb)
#
# --pre duckdb for compaction only: iceberg_rewrite_data_files() exists on the 1.6.0 dev
# line and nowhere else, and compact_iceberg.py degrades gracefully without it
# (has_rewrite_function). It floats rather than sitting on one hand-bumped build.
